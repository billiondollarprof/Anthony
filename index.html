Where the time goes on a build

Most of the work happens before any code is written.

Planning and researchThe hardest part. Once I can picture how a non-technical person will use it daily, the project is nearly done.
InterfaceDesigned for every screen size.
BackendAPIs, tool calling and the first pass of the logic.
TestingEdge cases, then fixes to the interface and flow.

Agents test their own work

Rule files make each AI agent click through the flows and screenshot the interface across screen sizes before I review anything.

Add lines, don't rewrite

When something already works, I have the AI add only the new lines. If it breaks, the cause is easy to find and I can revert.

Duplicates stopped in the database

For anything that costs money or must happen once, like a message or a payout, I set a database rule. A retry then can't send or spend twice.

Written handover

Each project keeps a README plus CURRENT, SESSIONS and PENDING-DEPLOYS files, so a new engineer or agent can pick up in minutes.

A safe way back

I keep a production branch and a testing branch, save known good states, and revert first. Then I work out what went wrong.

New tools by screenshot

When a platform is new to me, I screenshot the confusing screens and share them with the AI. Three or four are usually enough to work on my own.
